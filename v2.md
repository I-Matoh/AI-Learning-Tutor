# AI Learning Tutor V2: Premium Upgrade Blueprint

## Objective
Transform the current app from a strong demo into a premium learning product that feels trustworthy, personalized, and worth paying for.

## Current Snapshot
- Web experience has a polished visual layer and clear onboarding.
- Core value loop works: topic -> generated course -> lesson -> quiz -> unlock progression.
- Mobile app currently covers auth only (no real learning experience yet).
- Most learning intelligence, usage tracking, and persistence are client-side (`localStorage`), which limits trust and scale.
- Backend currently protects auth and basic routes, but does not own generation orchestration or premium analytics.

## What "Premium" Should Mean Here
- Reliable outcomes: users can feel real skill progress, not just content generation.
- High trust: stable quality, transparent limits, durable progress across devices.
- Thoughtful UX: faster, calmer, and more intentional than generic AI tools.
- Strong product depth: habit loops, coaching, diagnostics, and measurable milestones.

## Top Gaps Blocking a Premium Feel

### 1. Product Depth Gap
- Learning flow is mostly single-session consumption; limited adaptive coaching and weak long-term progression systems.
- No durable mastery model (confidence score, spaced repetition, weak-topic tracking).

### 2. Trust & Data Durability Gap
- Progress and quotas are primarily in browser storage.
- AI generation key is exposed client-side and generation is not fully mediated server-side.
- Usage endpoint is placeholder-level, so "limits" and "premium tiers" cannot be trusted.

### 3. Architecture Gap
- Web app logic is heavily concentrated in `frontend/App.tsx`, making iteration slower and riskier.
- Missing clear domain boundaries: learning engine, content generation, progress tracking, and billing readiness.

### 4. Mobile Product Gap
- Mobile currently feels like an auth shell, not a companion learning product.
- No parity with core web learning loop.

### 5. Commercial Readiness Gap
- No plan/tier system, no entitlement checks, no upgrade moments, no premium outcomes framing.
- No instrumentation to prove value (retention, completion rate, quiz pass lift, weekly streaks).

## V2 Roadmap (Prioritized)

## Phase 1 (0-3 weeks): Foundation for Trust and Premium Perception

### A. Move AI Generation Behind Backend
- Create server endpoints for course/lesson/quiz generation.
- Keep model keys server-only; remove direct client model calls in production mode.
- Add per-user usage ledger in database (not only IP/localStorage).

### B. Persist Learning State in Supabase
- Store courses, module/lesson completion, quiz attempts, and timestamps.
- Sync across web/mobile and support resume from any device.
- Keep local cache for speed, but DB as source of truth.

### C. Break Up Frontend Monolith
- Split `frontend/App.tsx` into feature modules:
  - `features/onboarding`
  - `features/course-map`
  - `features/lesson-viewer`
  - `features/quiz`
  - `features/auth`
- Introduce typed service layer and shared state boundary.

### D. Improve Perceived Quality
- Add skeleton states and progressive loading for course/lesson/quiz steps.
- Improve empty/error states with recovery actions (retry, switch depth, regenerate section).
- Add a clear "last saved" and sync status indicator.

## Phase 2 (3-8 weeks): Learning Intelligence That Feels Premium

### A. Mastery Engine
- Add lesson-level mastery score based on quiz performance and retries.
- Track weak concepts and surface targeted refresh lessons.
- Add spaced repetition queue with due dates and reminders.

### B. Better Assessment Quality
- Use multi-type checks (MCQ + short answer + scenario decisions).
- Add feedback quality rubric: not just right/wrong, but why and what to improve next.
- Store attempt history and show trendline improvement.

### C. Personalized Learning Pace
- User-selectable pace profiles: `Sprint`, `Balanced`, `Deep Work`.
- Auto-adjust lesson depth and quiz complexity based on performance.

### D. Progress System
- Add weekly goals, streaks, milestone badges tied to meaningful skill outcomes.
- Add "Learning Health" dashboard: consistency, completion velocity, weak-topic map.

## Phase 3 (8-12 weeks): Premium Business Layer

### A. Plans and Entitlements
- Define tiers (example):
  - `Free`: limited generations + basic course path
  - `Pro`: higher limits + full history + mastery dashboard
  - `Elite`: coaching mode + advanced diagnostics + exports
- Enforce capabilities server-side via entitlements.

### B. Upgrade Surfaces
- Add contextual paywalls at high-intent moments (after completion streak, after weak-topic insight).
- Show concrete value unlocks (not generic "go premium").

### C. Proof of Value
- Add portfolio artifacts: completion certificates, competency summaries, shareable progress cards.
- Add exportable learning reports for career/education use.

## UX & Brand Upgrades (Premium Feel)

### Information Architecture
- Make primary nav outcome-driven: `Roadmap`, `Today`, `Practice`, `Insights`, `Account`.
- Promote "Today" view for next best action to reduce cognitive load.

### Interaction Design
- Add smart transitions between lesson -> quiz -> feedback -> next step.
- Keep motion subtle and purposeful; reinforce achievement moments.

### Copy System
- Shift copy from "content generation" to "skill progression" language.
- Replace generic prompts with high-confidence guidance and measurable milestones.

### Trust Signals
- Remove or qualify partner logos unless there are real partnerships.
- Add transparent AI disclaimer + quality commitment + privacy posture.

## Mobile V2 Requirements
- Implement full learning loop on mobile (roadmap, lesson reading, quiz, completion).
- Add offline-first lesson caching + sync when online.
- Add notifications for spaced repetition and weekly goals.
- Keep interaction model native (snack-sized practice mode).

## Engineering & Quality Upgrades

### Testing
- Add unit tests for generation parsers, progression logic, unlocking rules.
- Add integration tests for auth + generation endpoints + entitlements.
- Add end-to-end happy path for onboarding -> complete lesson -> pass quiz.

### Observability
- Add structured logs around generation latency/errors.
- Capture product metrics: activation rate, D7 retention, weekly completed lessons, quiz pass rate.
- Set alerts for error spikes and model failure rates.

### Security
- Keep AI keys server-side only.
- Add database RLS policies for all user learning data tables.
- Move from in-memory rate limiting to Redis-backed limits for production scale.

## Suggested Data Model Additions
- `courses`
- `course_modules`
- `module_lessons`
- `lesson_attempts`
- `quiz_attempts`
- `mastery_scores`
- `usage_events`
- `subscriptions`
- `entitlements`

## 12-Week Success Metrics
- +30% increase in week-1 retained users.
- +25% increase in lesson completion per active learner.
- >=70% of active users complete at least 1 quiz/week.
- <2% generation failure rate.
- >=15% free-to-paid conversion once plans launch.

## First 10 Tickets to Create
1. Backend `POST /api/generate/course` with auth + quota checks.
2. Backend `POST /api/generate/lesson` with context and telemetry.
3. Backend `POST /api/generate/quiz` with retry-safe schema validation.
4. Supabase schema for courses/progress/attempts.
5. Frontend migration from `localStorage`-primary to DB-primary state.
6. Split `App.tsx` into feature folders and route-aware screens.
7. "Today" dashboard with next recommended action.
8. Mastery score computation and weak-topic tracking.
9. Mobile roadmap + lesson + quiz screens with sync.
10. Entitlement middleware and initial plan-gating UI.

## Bottom Line
The app already looks good; V2 should focus on durable learning outcomes, trustable backend ownership, and premium progression systems. If you execute Phase 1 and 2 well, monetization in Phase 3 becomes natural instead of forced.
